# CONVENTIONS.md — Cancer Transcriptomics Teaching Suite

Project rules for agents and humans in this repository, imported by `CLAUDE.md`. The repo is scaffolded from `codebase_template`, whose rules are in `AGENTS.md`. Where `CONVENTIONS.md` conflicts with `AGENTS.md`, `CONVENTIONS.md` wins; each divergence is a D-entry in `knowledge/decisions.md`.

## Read first, every session

1. `knowledge/lessons.md` — rules written after corrections; apply them.
2. `TODO.md` — the plan; work only on unchecked items of the current phase.
3. This file.

## Workflow

- Plan mode for any task with 3+ steps or an architectural choice. Write the plan (checkable items) into `TODO.md`, check in before implementing, mark items done as you go, add a short review section when a phase completes.
- Verify before done: run tests, execute the CLI on fixture data, open the HTML offline, measure wall time and peak RAM (the ctx reproduction block; for other commands `/usr/bin/time -l` on macOS, `-v` on Linux). Never report a module complete without this evidence.
- After any correction from the user, add a rule to `knowledge/lessons.md` in the same session.
- Use subagents for research, dataset scouting, and parallel exploration; one task per subagent.
- If something goes sideways, stop and re-plan; do not push through.
- Doc edits: targeted string replacements with grep verification, never whole-file rewrites.
- Never fabricate accessions, versions, or URLs: search, then record with the source, or flag as unverified.
- No access tokens or PATs in the repo or in chat.

## Stack

- Python 3.12; environment via `pixi` (channels: conda-forge, bioconda); containers via multi-stage Docker from the template, Apptainer SIF for HPC.
- CLI package `ctx` (typer). Layout and module list: see `TODO.md` → Repository. One subcommand per module: `ctx setup | gather | qc | process | quant | de | function | proteo | ncrna | genecard | clinical | report | lite-build`, plus, from Phase 2D, `ctx run | figure | source | verify-figure` and the global `--cohort`, and `ctx guide`, the custom-data page (TODO.md U.9), and `ctx reads`, a student's own FASTQ files laid out as a download (D-059).
- Cancer type is a first-class parameter (Phase 2D): `--cohort` selects a bundle in `conf/cohorts/<cancer>.toml`, which lists the cohort's dataset files per Step and module with its laptop caps and teaching notes; contrasts, covariates, sanity rules and worked-example genes stay in the dataset files. No cohort-specific logic in module code.
- Runtime profiles `laptop` (default) / `hpc`, and `lite` once the Phase 5 JupyterLite site exists; thread and memory budgets come from the profile, command syntax does not change.
- Budgets: Track A < 15 min and < 6 GB peak RAM on 4 cores; Track B < 10 min and < 4 GB. Every report states the measured values.
- Tables: Polars, lazy where possible, chunked concat, downcast to Int32/Float32 only after checking the value range, print `estimated_size()` for every materialised frame. Pandas only inside JupyterLite notebooks at the pydeseq2 boundary in `ctx.de.deseq`, which pydeseq2 requires, and at the lifelines boundary in notebook 10, whose fitters take a pandas DataFrame; M10's survival in `ctx.clinical` is numpy, checked against R survival (D-055).
- Raw reads enter through nf-core/fetchngs for public data, pinned `-r 1.12.0` (TODO.md D18) and run with `--nf_core_pipeline rnaseq --monochrome_logs true` into a fresh outdir (on Kebnekaise, `monochrome_logs = true` goes in `<project_dir>/nfcore_fetchngs/nextflow.config`: the lab launcher takes no extra flags and starts Nextflow in that directory, whose `nextflow.config` Nextflow reads). Inside a ctx root that outdir is `data/raw/<slug>/`, never `./results/`; the Kebnekaise lab script's `nfcore_fetchngs/results/` is copied there unchanged. A student's own FASTQ files enter through `ctx reads` (`ctx.gather.own_fastq`, standard library only, run as a file on Kebnekaise), which writes both outdirs `fetchngs.sbatch` writes in a run folder, under fetchngs 1.12.0's columns, MD5s computed, each file linked and never moved or copied (D-059). `ctx gather` is the only ctx module that reads that layout (`samplesheet/`, `fastq/`, `fastq/md5/`, `metadata/`, `pipeline_info/`), from either source through the same checks, and it never writes into it; M3's laptop route (`ctx process --genome`, Track A) opens the FASTQ files the harmonised sheet names, relative to `--fetchngs-dir`, and nothing else of it (D-031); M2 opens none (D-116); gather parses the samplesheet and metadata tables by column name, never by position or row order, because fetchngs fixes neither the `metadata/*.runinfo_ftp.tsv` row order nor the samplesheet sort key (1.12.0 sorts per-sample files by name, 1.13.0 sorts rows as text; D-006); every later module reads the harmonised sample sheet in `outputs/01_gather/`. Never write custom ENA/SRA download code (D-006).
- Two routes run the pipelines. The student route, on a laptop or a Slurm cluster, is one launcher per pipeline, `scripts/bash/fetchngs.sbatch` and `rnaseq.sbatch`, with Nextflow from the pixi `fetch` environment (pinned `==`, both platforms) and the computer chosen by `CTX_SITE` (`scripts/bash/site_<name>.sh`): the default `kebnekaise` runs each task as a Slurm job under Apptainer, `laptop` runs every task under Docker, with `docker,arm` for fetchngs and `docker,arm64` for rnaseq on Apple silicon; `ctx guide` writes its commands from the launchers' Usage blocks (TODO.md U.4, U.9). The instructor route that fetched Step-1 is the shared HPC2N Nextflow through the lab's `SHARED_run_fetchngs.sbatch` on Kebnekaise. fetchngs 1.12.0 on Nextflow 26 needs `NXF_SYNTAX_PARSER=v1`, which `fetchngs.sbatch` sets. Every Slurm job is named `<ANALYSIS>_<PROJECT>_<PROCESS>_<VERSION>` by `scripts/bash/job_name.sh` alone: `RNAseq-Tutorial`, the run folder's dataset slug, `nf-head` or `nf-<task>(<tag>)` or the launcher's step, and `NA`, no field holding `_` (Rytis 2026-10-23).
- Step-1 counts come from nf-core/rnaseq -r 3.27.0 (`ctx.gather.rnaseq.RNASEQ_VERSION`; TODO.md D21), with Salmon alone (`pseudo_aligner: salmon`) on every site and, where the site aligns (`SITE_RNASEQ_ALIGN`, Kebnekaise), STAR with Salmon on its alignment (`aligner: star_salmon`) beside it; a laptop keeps `skip_alignment: true` (D-113). M1, M4 and M5 read Salmon alone's matrix; M2's read stage and M3 read nf-core's own outputs, never a hand-written alignment (D-113). Fed by the fetchngs samplesheet cut to `sample, fastq_1, fastq_2, strandedness`, under `NXF_SYNTAX_PARSER=v2`; `ctx gather` refuses any other release and an aligned outdir that lacks a file of `rnaseq.ALIGNED_FILES`. What leaves Kebnekaise is `rnaseq.CLUSTER_FILES`: Salmon alone's files, Salmon on STAR's matrix and the 20 tables nf-core's own MultiQC wrote, never a BAM; the MultiQC report stays on the cluster (D-116).
- Bioinformatics tools (bioconda), in the `reads` pixi environment outside the analysis solve and called by subprocess through `ctx.tools`, which refuses any version other than the pin (D-027): FastQC, fastp, seqkit, MultiQC, STAR, HISAT2 (optional), samtools, subread/featureCounts, Salmon, Trim Galore. Python: pydeseq2, ctx's own tximport port `ctx.quant.tximport` in place of pytximport (GPL-3.0, pandas; D-054), gseapy, decoupler (optional), pysradb, GEOparse, cptac (verify), scikit-bio, scipy, statsmodels, lifelines (notebook 10 only; D-055), openpyxl (M7, M10; D-055), plotly, seaborn, matplotlib, jinja2, typer, pytest, ruff, mypy, interrogate.
- Pin every version in `pixi.toml`; record data-release identifiers (GDC release, GENCODE, MSigDB, TargetScan, miRTarBase, PDC) in the `_README.md` of each output.

## Code rules

- Google-style docstrings with type hints on every function and class; `interrogate` at 100 % for `src/`.
- `ruff` clean, `mypy` clean on `src/`.
- Tests in `tests/` run on chr22-sized fixtures in < 5 min total; every module has an end-to-end test.
- Elegance check before presenting non-trivial code: "is there a simpler way; am I reinventing a wheel?"

## Outputs

- File naming: `YYYY-MM-DD_<module>_<description>_v<X>.<ext>`; the description is words joined by underscores, each word letters and digits joined by single hyphens, no spaces, so a dataset name made from its label fits: `2026-10-23_de_Breast-tissue-BRCA_overview_v1.html` (D-114). A lint (`ctx.io.naming`) enforces this.
- Every data output gets a companion `_README.md`: creation timestamp, source script and commit, tool and data versions, and a data dictionary (one row per column: name, type, unit, meaning).
- `data/` and `resources/` are never committed; `ctx setup` fetches resources with checksums; `ctx genecard` alone writes `resources/cache/`, with its own manifest (TODO.md M9). External inputs (fetchngs outdirs, GDC and Xena downloads) sit under `data/raw/` as fetched. Writers: modules write only under `<root>/outputs/NN_<module>/`, `ctx setup` under `resources/`, `ctx genecard` under `resources/cache/`; from Phase 2D, `ctx figure` run from a Reproduce panel writes into the reader's own working folder, outside any ctx root.

## Figures

- Every figure exists as `_white` and `_black` PDF and SVG from one render (Seaborn/Matplotlib, vector), one HTML with a light/dark toggle (Plotly), and its numbers as CSV with `_README.md` (TODO.md D16). One data contract per figure type; `static()` and `interactive()` render from the same object.
- Style: Okabe–Ito palette in this order — #E69F00, #56B4E9, #009E73, #F0E442, #0072B2, #D55E00, #CC79A7, #000000. Sizes and parameters of the Candida Ribo-seq figures (Rytis 2026-09-29, D-024), set in `ctx.viz.style` alone: every figure 170 mm wide, the double column (`style.FIGURE_WIDTH`, Rytis 2026-10-01); Liberation Sans, from ctx's vendored copy on every machine, then Arial and DejaVu Sans for a viewer without it (Rytis 2026-10-20, D-097); 12 pt panel letters (bold capitals), 10 pt axis titles, 9 pt ticks, legends, annotations and captions, nothing below 8 pt; 1 pt axes and lines, 1.5 pt boxes and error bars, 3 pt for one line per sample, each a unique colour and dash from the data colours at 3:1 or more on both themes (`style.distinct_styles`, Rytis 2026-09-30); 3 pt ticks, outward; 6 pt points at alpha 0.5; no seaborn context; `sns.despine()`, `plt.tight_layout()`; no chart junk.
- Plotly: `plotly_white` base plus a custom dark template; hover shows every variable a reader would ask about; exact p-values and n in the caption printed once under each interactive figure, not inside the plot (D-011); the PDFs keep theirs in the figure.
- Controls (D-051, Rytis 2026-10-01): wherever the data allow one, an interactive figure carries a page control that changes what it shows or selects data (a threshold, a filter, a grouping, what is plotted, a selection painted across views), recomputed in the page; a figure without one records why. The PDF and SVG buttons export the view as set.
- Continuous values (filled contours, colour bars) use cividis in both themes, with isolines and their labels in ink; Okabe–Ito stays for categories, including per-group contour lines. Contour plots only for a continuous value over two continuous axes (computed surfaces, or densities from ≥ 30 points per group), never for categorical axes; density levels are 50 % / 90 % highest-density regions from one grid shared by both renderers.
- Statistical annotation is mandatory: test name, n per group, adjusted p (BH) or FDR, effect size, and the caption block written by `ctx.viz.annotate`. A figure without its test is not finished.
- External summary data (GTEx, HPA) get descriptive annotation only (n, median, IQR, tau, release); never inferential tests on external medians. Descriptive figures are the exception to the mandatory test above: M1's counts, the QC bands and external summaries say "no test" in their caption, and an external panel's caption also names the release and retrieval date.
- From Phase 2D, every figure has a stable ID (`<cohort>_<module>_<figure>`) and a parameter model as a frozen dataclass with one loader that reports every error together, and is produced only through `ctx figure <id>`. Its Reproduce panel is generated from the `FigureSpec` (environment, inputs with checksums, params heredoc, generate naming the plotting file, check; upstream collapsed); never hand-write panel commands. Pasted blocks contain no `set -e`; the downloadable script uses `set -euo pipefail`.
- Fonts: PDFs embed fonts as Type 42; every figure is set in ctx's vendored Liberation Sans, Arial's redistributable metric twin, registered with matplotlib before any figure and ahead of any installed copy, so a figure drawn where Arial exists embeds the face its redraw in the figures image embeds (D-097); figure files carry no creation timestamp.

## HTML reports

- Self-contained single files: `plotly.min.js` embedded, no CDN, no external requests except optional gene links opened on click. Size < 15 MB; heatmaps capped at 100 genes; embedded tables capped to tested genes with ≤ 8 columns.
- Design of the ALI report (D-024): a frosted sticky top bar, an eyebrow above the title, numbered sections under hairlines, white cards with a soft shadow on a near-white page, stat tiles, rounded table wraps, tinted callouts for practice and mistakes; a skip link and focus rings, which ALI lacks; every text colour at 4.5:1 or more on each surface it sits on (`tests/test_report.py::test_text_contrast`). Theme toggle via CSS variables and `Plotly.relayout`; an 18 px page base; the interactive plots at the figure sizes plus 3 pt, converted to px at 96/72 (`ctx.viz.style.on_page`, Rytis 2026-09-28), then text, points and marks 25 % larger (`PAGE_SCALE`, Rytis 2026-09-30); the PDF and SVG keep the journal sizes; Okabe–Ito. The plot is the largest part of its card (D-117, Rytis 2026-10-23): its legends in a row above or below it, "How to read this" under it across the card at every width, its lines in columns where wide; the content column grows with the window from 1,072 to 1,600 px (`LAYOUT["content-wide"]`); and the page script (`_page_fit.js.j2`, `wanted`) draws every plot that holds no aspect of its own at least 9/16 of its width tall (`style.PAGE_PLOT_ASPECT`) and, wider than 640 px, larger than its legend and reading guide together; a phone keeps its own heights.
- Report sections, in this order, with these labels verbatim: Purpose · Input · Method · Parameters (parameter, meaning, default, effect of changing it) · Results · Interpretation · Questions (`<details>` answers) · Pitfalls · Reproduce (exact command, wall time, peak RAM, versions) (Rytis's draft v3.11, D-045). The core edition's lite pages show only figure and results-table cards, each figure with its lead, reading guide and controls, D-111; on every page the reading guide (two lines in a page file) and each caption after its first sentence are folded and open on a click, while the PDF, SVG and export keep the whole caption, D-119.
- Report prose: direct and minimal; every sentence changes what the student does or understands. Declarative for facts, imperative for actions; no "we", "let's", "you will", no narration of the module's own steps. A computed number in place of a general statement, from a `{placeholder}`, never typed. No figurative language for software or data (know, bring, want, tell and arrive in every form), no intensifiers, none of the words `ctx.report.prose.BANNED` lists. No question outside the Questions section: no `?` in a title, heading, lead or sentence (D-048). Sentences at most 25 words, paragraphs at most 3 sentences. Words: Purpose 30, Input 40, Method 90, each figure caption 40, Interpretation 120, Questions and Pitfalls 3 items of 20, a card's meaning and effect 12 each. `pixi run lint-prose` checks every page file in `content/` and the cards; CI fails on a violation.
- Page text lives in `src/ctx/report/content/*.toml`, one file per page plus `ui.toml` and `cards.toml`, read through `ctx.report.text`; code names a key and fills its `{placeholders}`, never writes a sentence (D-024, Rytis 2026-09-29). Setup and gather do so now; M5, M6, the hub and the captions move after the Step-1 record (P2S.4). An unfilled placeholder or an unread key fails a test.
- Every parameter exposed in the CLI must have a parameter card; a test reads CLI defaults and fails if a card is missing or stale.

## Glossary and term tooltips

Rytis's draft v3.12, merged in D-048.

- `src/ctx/report/glossary.yaml` is the source, read by `ctx.report.glossary`; in a notebook, `explain("phred")` prints one entry. Fields: `id` (snake_case anchor), `term`, `aliases` (a list, may be empty), `category` (one of 14), `short` (the tooltip, at most 20 words), `long` (the glossary page, at most 60), none of them blank, and optional `rna_vs_dna`, `typical`, `source`, `see_also`, `confirm`. No two entries share a name: id, term or alias, in any case.
- Definitions follow the prose rules, banned words included, except the typed number: a definition states numbers, and an entry that does carries a `source`, never invented. A number without a source and `confirm: true` are lint warnings now and errors at a `v*` release tag.
- Page text marks jargon as `[[term]]` (an id, term or alias, in any case, except that a name of three characters or fewer or with two capitals, such as OS, GO or rho, matches only as written: D-104), `[[term|display]]`, or `[[term!]]` to force the icon, in a page file's sections, questions, pitfalls and figure captions and in the cards; the lint refuses a mark anywhere else. The first mention per section carries the icon, so mark the first mention where it helps, never every word. A mark inside backticks is code. Off the page a mark is its display text: a caption's in the PDF and SVG, a card's in `--help`; a figure refuses a mark anywhere but its caption (`ctx.viz.save`).
- The icon is a circled i, 0.7 em, at the phrase's top right, in the link colour (not #0072B2: D-024 keeps data colours off page furniture), in a 24 px target. The tooltip (`templates/_glossary.js.j2`, no library) opens on hover and on focus; a click or tap pins it or closes it; Escape, an outside click and blur close it; one is open at a time; it has `role="tooltip"` and `aria-describedby`, flips to stay in view, and links "Glossary" with no arrow. It is `position: fixed`, so a scrolling table cannot clip it: no ancestor of a term may set transform, filter, backdrop-filter, perspective, contain or will-change. A page embeds only the entries it marks.
- The glossary page is `outputs/09_report/<date>_report_glossary_v1.html` in each ctx root, written with the first page of the day that links it; module pages link it from the top bar and every tooltip, and so does the hub. The kit copies it with the pages that link it, and `START.html` links the newest. A page written outside a ctx root (from Phase 2D, `ctx figure` in the reader's folder) keeps its tooltips and links no glossary.
- `python -m ctx.report.glossary_lint` (and `tests/test_glossary.py`) checks the schema, names, budgets, prose rules, `see_also` targets, numbers without a source and `confirm` flags, and every mark in the page files; a glossary term whose first mention in a section is bare, marked later or not at all, is listed as a warning.

## Statistics rules

- Multiple testing: BH everywhere, stated in the figure. Report effect sizes next to p-values.
- DE: pre-filter by expression (edgeR-style rule) before pydeseq2; paired or nested designs when the data have them; show the p-value histogram and dispersion plot as health checks; shrunken and raw LFC both available, shrinkage on unless `ctx de --no-lfc-shrink` turns it off (D-019).
- ORA uses an explicit background of tested genes; GSEA uses the Wald statistic, 1000 permutations, seed 42, min size 15, max size 500.
- Proteomics: missing values are not zeros; restrict tests to proteins quantified in ≥ 70 % of samples; state TMT batch design.
- Non-coding: stratify by biotype; never claim miRNA quantities from standard RNA-seq; predicted and validated targets shown separately.
- Cross-study comparisons are labelled as such with batch diagnostics beside them.
- Survival: the endpoint is chosen per TCGA-CDR's recommendations (Liu et al. 2018, Table 3) and named in every figure; continuous Cox is the primary model; Kaplan–Meier splits are pre-specified, and any data-driven cut-off carries the corrected p of the maximally selected statistic; the PH assumption is tested and reported; every KM plot has a risk table and censor marks.
- Treatment: TCGA tumours were sampled before systemic therapy for them (exclusionary on TCGA's case quality-control forms), with exceptions GDC notifies: neoadjuvant therapy (42 patients in the CDR, 102 GDC notifications) and treatment for a prior malignancy, so expression by treatment is never presented as a treatment effect; treatment effects come only from pre/on-treatment datasets (TODO.md D28).
- QC bands live only in `conf/qc_metrics.toml`; every band has a source and a source type, course conventions are labelled as such, and no QC threshold is hard-coded elsewhere, except the sex check in `ctx.de.run.sex_check`, frozen with M5 until the Step-1 record; after it the check moves to `ctx.qc.identity` and M5 imports it from there. MultiQC, pinned in the `reads` environment (D-027), is the only parser of tool QC logs, read through `ctx.qc.multiqc_io`. M2's read stage and M3 read the tables nf-core/rnaseq's own MultiQC wrote, in place (`multiqc_io.nfcore`, the same MultiQC 1.35), and run no tool and no MultiQC over its outdir; ctx computes only what nf-core does not, and draws every figure (D-116).

## Data and scope boundaries

- TCGA raw reads are controlled-access; only processed expression from GDC is used. Do not attempt dbGaP data.
- Step-1 dataset: E-MTAB-11190, ENA PRJEB49000 (confirmed 2026-09-27, `TODO.md` D5; read length is confounded with the cancer groups and is taught, never hidden); fetchngs takes it as its ENA study accession (ERP or PRJEB), because it rejects `E-MTAB-*`. Cohort identifiers never go in `src/`, `tests/` (except the D20 fixture of nf-core's own test IDs), `scripts/`, `pyproject.toml` or `pixi.toml` (`tests/test_repo.py::test_no_cohort_identifiers`). Indices are prepared once on HPC and hosted on Zenodo; students never download full FASTQs. Read-level pages (M2's read stage, M3) show all Step-1 runs, aligned on the cluster, and the 8-run teaching subset is removed (D-115); the release kit holds no made-up page (D-050).
- External knowledge bases (GTEx, HPA, Ensembl): documented APIs and bulk files only, cached under `resources/cache/` per release with the retrieval date and the SHA-256 measured on arrival; never scrape, mirror or iframe their pages; cite HPA per its licence page: a primary publication, proteinatlas.org, and the versioned URL `v<NN>.proteinatlas.org`.
- Clinical data: open-access, de-identified only; harmonised vocabulary with explicit missingness; GDC annotations are read and logged, and any exclusion made from them is the course's own rule, stated on the page (the neoadjuvant and prior-malignancy annotations are notifications; only a redaction removes a case).
- Licences: code MIT, materials CC BY 4.0; respect KEGG, COSMIC, DisGeNET and miRTarBase terms (documented in `docs/`). CC BY 4.0 content (HPA, AlphaFold 2) may be embedded with its citation; link, never embed, what HPA lists under user terms (Ensembl, GTEx, TCGA, Tabula Sapiens, IntAct, BioPlex, OpenCell, TFClass, DepMap) when taken from HPA, AlphaFold 3 (CC BY-NC-SA 4.0) and CC BY-SA sources such as IUPHAR, TCDB and Metabolic Atlas; GTEx and Ensembl data taken from their own files or APIs follow their own terms: GTEx data are drawn as our own figures, implying no endorsement, with the GTEx Portal's dated acknowledgement and a line that newer GTEx data may exist (GTEx licence page, read for the M9 plan 2026-10-07; Rytis 2026-10-08); since V11 has no API, M9 reads GTEx V11's release files, registered by `ctx setup`.
