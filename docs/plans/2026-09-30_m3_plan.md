## 3. Decisions for you, and what gets built meanwhile

### R1. How STAR runs on Apple silicon

This is a course decision, not a Mac quirk. Pixi on Apple silicon is a first-class student platform.

The pinned osx-arm64 build has two faults:
- it reads 0 reads, because libc++ ignores `setbuf` (STAR issue #2632; the fix, PR #2691, was never merged);
- `--quantMode GeneCounts` exits 109, for a cause that is UNVERIFIED and may be separate.

Options:
- **A. Container.** A digest-pinned container runs STAR only, behind an explicit per-tool engine switch (`CTX_STAR_ENGINE=native|container`). The budget then counts the container's peak memory and the Docker VM's resident memory (1,067 MB idle, review 3). Two possible images:
  - the local wave image, which is third-party and outside pixi.lock; how it reached this Mac is UNVERIFIED;
  - a project `reads` image built from pixi.lock and pushed to GHCR. That needs linux-aarch64 added to the reads feature (pixi.toml:81 lists only linux-64 and osx-arm64).
- **B. HISAT2 on Apple silicon.** STAR runs on Linux: CI, the cluster, and students on Linux.
- **C. A STAR build with PR #2691's change.** It is off the pin, and may still hit the GeneCounts fault.

**Built meanwhile:** B in practice.
- `--aligner star` stays the default everywhere.
- On a failing STAR, a probe at the door refuses and names both routes. It never falls back to another aligner on its own.

**Not added:** `--adapter`. fastp auto-detects the adapter on 1M-read files, and M2 already teaches adapters. Add it only if M3.9 shows fastp finding no adapter where M2 reports adapter content.

**Every input problem is listed together**, then exit 1:
- no gather sheet: `newest` raises "run the earlier module first";
- the dataset file's slug differs;
- `annotation_gtf` is undeclared, missing on disk, or has the wrong SHA-256;
- `--genome` is not a file;
- the genome and GTF share no contig: the first 10 names of each are listed;
- the start-codon ATG share is under the registry's `usable` band;
- a mix of paired-end and single-end runs;
- `--featured-sample` is unknown;
- `--multimap-max` is out of range, or given under hisat2;
- an unknown `--settings` token;
- `--compare-dataset` lacks its counts table or a needed column. The column is checked before use, because a zero from a missing column is not a result;
- the STAR probe fails. The message names D-036 and gives both routes, and no page is written;
- the auto strand call is "undetermined" for a run. The message names the runs and their shares and asks for `--strandedness`.

**Unit of alignment.** STAR and HISAT2 align per sample, with multi-run samples comma-joined. fastp and the cap act per run. All 210 Step-1 samples have n_runs = 1 (review 2), but the rule is tested anyway.

## 7. Order of operations, and the invariants

1. Resolve and check every input together (section 5).
2. Build the reference: genome facts, annotation SHA-256 against the declared value, subset, ATG share, gene types (full and subset), then the index or its reuse. Then the cut index when `cut` is requested.
3. Cap once per run, if a cap is set.
4. Trim every run with fastp. The capped raw file stays available for `untrimmed`.
5. Align every sample at the main setting. Then align the featured sample's settings: cut; untrimmed; unspliced under hisat2.
6. samtools on the main BAMs.
7. featureCounts plain at `-s 0/1/2`, then the MultiQC runs for these and the main MultiQC (aligner, samtools, fastp, with RAW_COUNTS).
8. Strand calls, which stop the run if any call is undetermined. Then `-O`, `-O --fraction` and `-M` at the called strands, and their MultiQC runs.
9. Invariants.
10. Gene tables, comparisons, agreement.
11. Tables, figures, page.

Each invariant raises ProcessError:
- **I1.** Aligner input reads equal fastp's passed reads for the sample's runs: halved for pairs, since STAR counts a pair once. For `untrimmed`, they equal the capped raw count. This is the D-036 guard; D-027 checked only `--version`.
- **I2 (STAR).** For each column, the Polars sum of gene rows equals MultiQC's "Overlapping Genes". The five categories sum to input reads. This is a check that the two parsers agree, not a biological claim (review 1, item 15).
- **I3.** featureCounts matrix column sums equal MultiQC's Assigned, for plain and for `-O --fraction` counting. Not for `-O` or `-M`, whose sums legitimately differ: facts measured `-M --fraction` summing to 1,527 against 1,537 Assigned.
- **I4.** Every count table's gene set equals the subset GTF's gene set.
- **I5.** featureCounts' matrix headers equal the main BAM paths in sheet order, and the `-s` list follows the same order.
- **I6.** Primary mapped % from MultiQC flagstat, computed as (mapped - secondary - supplementary) / (total - secondary - supplementary), equals the aligner's mapped %, unique plus multi.
  - Measured on se_c: 970 / 1,000 = 97.00 against STAR's 97.0.
  - Dropping `--outSAMunmapped Within` makes flagstat say 100 %, so I6 catches it.
  - The idxstats `*` line is not used: MultiQC keeps only [mapped, length], so it loses the unmapped count (review 1).

## 11. Statistics, defined once in `ctx.concordance`

- **Genes used.** Keep a gene when a + b > 0, filtered before any transform. A gene that is zero in only one method is kept.
- **Identical vectors.** Short-circuit: ρ = 1, CI [1, 1], n_identical = n, and no bootstrap is run. Review 1 measured percentile giving 0.9999999999999999 and BCa giving NaN on identical input.
- **Small n.** With n < 4, the CIs are null and the caption says so.
- **Spearman.** The estimate is `scipy.stats.spearmanr`.
  - The CI is `scipy.stats.bootstrap(paired=True, method="percentile", n_resamples=1000)` with seed 42, resampling genes.
  - Percentile, not BCa, because BCa's jackknife returned NaN on degenerate input. The choice is not about speed: BCa took 0.52 s against 0.36 s (review 2).
  - Resamples that give NaN are dropped and counted.
- **Pearson.** On log2(count + 1). The CI is `PearsonRResult.confidence_interval()`, which uses Fisher z; it equals tanh(atanh(r) ± 1.959964/√(n-3)) to 16 digits (design 3).
- **Bland-Altman.** d = log2(b+1) - log2(a+1).
  - Bias = mean(d), with a t-based CI.
  - Limits = bias ± 1.96·SD, with ddof 1.
  - The empirical 2.5 and 97.5 percentiles of d are shown beside them.
  - Fold = 2^bias, back-transformed as in Euser 2008. The text calls it "a difference of log2(count+1)", never a log ratio.
  - Confidence intervals for the limits are added only after Bland and Altman 1986 or 1999 is read in full. The √(3s²/n) form is UNVERIFIED.
- **What the intervals mean.** They are nominal. The genes are the whole chr22 set, not a sample, so the per-sample spread is the uncertainty the page leads with.
- **No hypothesis test**, so no BH. Lin's CCC appears only as a think prompt.
